# BankPro — Deployment Guide (Phase 8)

The public demo runs on three free services. None of them needs a credit card (checked October 2026 —
free plans change, so re-check the providers' pages before you rely on them).

| Part | Service | Free plan (Oct 2026) | Notes |
|---|---|---|---|
| Database | **Aiven for MySQL** | 1 CPU, 1 GB RAM, 1 GB storage, no time limit | Aiven may power off a free service that is not used in its first few hours (it emails you first; you can power it on again). |
| Backend (Spring Boot, Docker) | **Render** web service | 512 MB RAM, 0.1 CPU, 750 hours/month, 5 GB bandwidth | **Sleeps after 15 minutes without traffic**; the next visit waits about a minute while it starts. The sign-in page explains this to visitors. |
| Frontend (React) | **Vercel** | Hobby plan | Serves the built site over HTTPS with security headers from `frontend/vercel.json`. |

```
 Browser ──HTTPS──► Vercel (React app)
    │
    └──HTTPS /api──► Render (Spring Boot, Docker) ──TLS──► Aiven (MySQL 8)
```

The browser calls the API directly (allowed by CORS) rather than through a Vercel proxy, because a proxy
would time out while a sleeping backend starts.

**What you need:** your GitHub repository with all phases pushed, and about 30 minutes.
You create the accounts and paste the passwords yourself — never send them in chat, and never commit them.

---

## Step 0 — Try the production setup on your PC (optional, recommended)

This runs the same Docker images and settings as the hosted version, including the 512 MB memory limit.
In `.env` make sure `JWT_SECRET` has a value (Git Bash: `openssl rand -base64 48`). Then, in cmd from the repo root:

```
docker compose --profile app up -d --build
```

Open http://localhost:8081 and sign in with a demo account. Stop it with `docker compose --profile app down`.
(The first build downloads Maven and Node images and takes several minutes.)

---

## Step 1 — Database on Aiven

1. Sign up at https://aiven.io (GitHub or Google sign-in works).
2. **Create service** → **MySQL** → plan **Free**. Choose a cloud region; note which one (you will pick the
   nearest Render region in step 2). Name it `bankpro-db`. Create.
3. Wait until the status is **Running** (a few minutes).
4. On the service's **Overview** page, copy: **Host**, **Port**, **User** (`avnadmin`), **Password**, **Database name** (`defaultdb`).
5. Build the connection URL (replace HOST and PORT):
   ```
   jdbc:mysql://HOST:PORT/defaultdb?sslMode=REQUIRED&serverTimezone=UTC&characterEncoding=utf8
   ```
   `sslMode=REQUIRED` encrypts the connection; Aiven refuses unencrypted connections.

You do not create tables: the backend's Flyway migrations create the schema and the demo data on first start.

## Step 2 — Backend on Render

1. If your Aiven region is in Europe or the US, open `render.yaml` and change `region: singapore` to
   `frankfurt`, `oregon`, `ohio` or `virginia` (whichever is closest), then commit and push.
   The region cannot be changed after the service is created.
2. Sign up at https://render.com with your GitHub account.
3. **New** → **Blueprint** → connect your BankPro repository → Render reads `render.yaml`.
4. Fill in the four values it asks for:
   - `DB_URL` — the URL from step 1.5
   - `DB_USERNAME` — `avnadmin`
   - `DB_PASSWORD` — the Aiven password
   - `CORS_ALLOWED_ORIGINS` — for now `https://bankpro-crm.vercel.app` (you will correct it in step 4)

   `JWT_SECRET` is generated by Render automatically; `SPRING_PROFILES_ACTIVE` is already `prod,demo`.
5. **Apply**. The first build takes 5–10 minutes. In **Logs**, wait for `Started BankProApplication`.
6. Open `https://<your-service>.onrender.com/actuator/health` — it must show `{"status":"UP"}`.
   Copy the service address (e.g. `https://bankpro-api.onrender.com`).

If the log shows `Communications link failure`, the DB URL, port or password is wrong, or the Aiven service
is powered off. If it shows `JWT_SECRET must…`, delete the variable and let Render generate it again.

## Step 3 — Frontend on Vercel

1. Sign up at https://vercel.com with your GitHub account.
2. **Add New → Project** → import the BankPro repository.
3. **Root Directory**: `frontend` (click Edit). Framework preset: **Vite** (detected). Leave build settings as they are.
4. **Environment Variables**: add `VITE_API_BASE_URL` = `https://<your-service>.onrender.com/api`
5. **Deploy**. When it finishes, copy the production address (e.g. `https://bankpro-crm.vercel.app`).
   You can rename the project under Settings → General to get a nicer address.

## Step 4 — Connect them (CORS)

1. In Render → your service → **Environment**, set `CORS_ALLOWED_ORIGINS` to the exact Vercel production
   address — `https://`, no trailing slash. Save; Render redeploys (about 2 minutes).
2. Only that address can call the API. Vercel "preview" addresses (one per commit) are refused on purpose.
   If you add a custom domain later, list both, separated by a comma.

## Step 5 — Verify the live app

Automated read-only check (creates no data), in cmd:
```
cd e2e
npm install
npm run install-browser
set E2E_BASE_URL=https://bankpro-crm.vercel.app
set E2E_API_URL=https://bankpro-api.onrender.com
npm run smoke
```
It checks: API health, nothing extra exposed (Swagger off, data needs a token), CORS allows only your
frontend, security headers, deep links, and sign-in plus dashboard/customers/reports for officer, manager and admin.

By hand: open the Vercel address, sign in as `manager.motijheel@bankpro.demo` / `BankPro@2026`, and open the
dashboard, a customer, the lead board and a report.

## Updating the live app

Push to `main` on GitHub: Render and Vercel both redeploy automatically. Database changes go in a new
Flyway migration (`V3__...sql`); never edit applied migrations.

## Optional: keep the demo awake

A free monitor such as UptimeRobot or cron-job.org calling `https://<your-service>.onrender.com/actuator/health`
every 10 minutes stops Render from sleeping (one service uses about 744 of the 750 free hours a month).
Without it, the first visitor after a quiet period waits about a minute.

## Production settings (reference)

| Variable | Where | Value |
|---|---|---|
| `SPRING_PROFILES_ACTIVE` | Render | `prod,demo` — `demo` adds the fictional demo data; omit it for an empty system |
| `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` | Render | Aiven connection (TLS required) |
| `JWT_SECRET` | Render | generated; Base64, at least 32 bytes; changing it signs everyone out |
| `CORS_ALLOWED_ORIGINS` | Render | exact frontend origin(s), comma-separated |
| `DB_POOL_SIZE` | Render (optional) | default 5 |
| `VITE_API_BASE_URL` | Vercel | `https://<backend>/api` (read at build time — redeploy after changing it) |

The `prod` profile disables Swagger, exposes only `/actuator/health`, trusts the host's HTTPS proxy headers,
uses a 5-connection pool, and shuts down gracefully. The container caps the Java heap at half of the
512 MB limit; measured use after a full end-to-end run was about 370 MB in total.

## Limitations of the hosted demo

- Portfolio demonstration with **fictional data only**. Not certified, audited or compliant for real banking;
  do not enter real customer information.
- Anyone with the published demo passwords can sign in and change the demo data.
- Free plans: the backend sleeps when idle (first request ~1 minute), 512 MB memory, and the database has 1 GB storage.
  Login rate limiting is kept in memory and resets when the backend restarts or sleeps.
- The database connection is encrypted (`sslMode=REQUIRED`) but does not verify Aiven's certificate; for real
  systems use `sslMode=VERIFY_CA` with Aiven's CA certificate in a trust store.
- Demo records were created relative to the date of the first deployment, so "this month" figures shrink as time passes.
